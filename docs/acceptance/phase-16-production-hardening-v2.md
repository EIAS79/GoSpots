## Security dependency remediation

The first Phase 16 hardening run correctly failed the new production dependency audit. Runtime dependency remediation was then applied rather than weakening the gate:

- Next.js / eslint-config-next moved to the patched 16.2.11 line;
- Multer moved to 2.2.0;
- Sharp moved to 0.35.3;
- Nest Swagger resolution refreshed through the regenerated lock graph.

The frozen `pnpm-lock.yaml` was regenerated by an isolated branch workflow and the temporary lock-sync workflow was removed immediately after use.

Any remaining audit finding must be resolved or proven non-production/build-only with an explicit documented exception before this phase may be accepted.
